MCP Airline Demo

The companion to the IEEE talk “Connecting Enterprise AI Using MCP.”

One request, “Book me a cheap flight somewhere sunny this weekend and use my miles”, run four ways: the happy path, two ways it goes wrong, and the fix. Everything is synthetic and open-source. Tool-neutral: any MCP-capable client works.

3 purpose-built MCP servers no restarts between beats synthetic data MIT

What it is

An assistant composes three separate back-end systems over MCP to book a trip:

ServerWhy it's neededWhat it contains
reservationsFinds the flights and the weather, and records the booking3 tables: flights, airports (weather), bookings
loyaltyConfirms the traveler's miles so they can be applied to the fare1 table: members (miles balance, tier)
policiesThe refund & baggage rules the assistant must quote2 docs: refund-policy.md, baggage-policy.md

Each server reads its data fresh on every call. That is the whole trick: change a file between two questions and the next answer changes. No restart, no redeploy.

Each server re-reads its backend on every call, so the toggle scripts (use-stale.sh, break-miles.sh) change behavior with no restart, the point of the demo, and the source of both failures.

The takeaway. MCP composes real systems live (Beat A). The same flexibility means a stale source (B) or an unhandled tool error (C) produces a confident wrong answer. The fix is a rule: quote your source, fail closed (D). A system prompt here; code in production.

Want to run this for real on your machine? → open the Run it yourself tab above.

🖥 Laptop / desktop only. Running the demo needs a terminal and a desktop MCP client. There's nothing to install on a phone. macOS, Linux, and Windows all work.

Prerequisites

  • uv runs the three purpose-built Python servers and provisions the pinned mcp SDK on first launch: curl -LsSf https://astral.sh/uv/install.sh | sh
  • A desktop MCP client, e.g. Claude Desktop, Claude Code, or the OpenAI Codex CLI. Any MCP-capable host works.
  • Python 3 (stdlib only) seeds the synthetic databases
  • Node.js, optional, only for the off-the-shelf fallback setup (the filesystem server via npx)

1 · Clone & seed

git clone https://github.com/agnitrip/mcp-airline-demo.git
cd mcp-airline-demo
./scripts/setup.sh        # seed synthetic DBs + clean baseline
./scripts/status.sh       # -> reservations CURRENT, loyalty healthy, policies CURRENT

2 · Wire the MCP host

Add the three purpose-built servers to your client's config. Replace /ABSOLUTE/PATH/TO/mcp-airline-demo with the real path. The host needs the absolute path to each server script.

{
  "mcpServers": {
    "reservations": {
      "command": "uv",
      "args": ["run", "--with", "mcp[cli]<2",
               "/ABSOLUTE/PATH/TO/mcp-airline-demo/servers/reservations_server.py"]
    },
    "loyalty": {
      "command": "uv",
      "args": ["run", "--with", "mcp[cli]<2",
               "/ABSOLUTE/PATH/TO/mcp-airline-demo/servers/loyalty_server.py"]
    },
    "policies": {
      "command": "uv",
      "args": ["run", "--with", "mcp[cli]<2",
               "/ABSOLUTE/PATH/TO/mcp-airline-demo/servers/policies_server.py"]
    }
  }
}
The --with "mcp[cli]<2" pin is required. The servers target the 1.x low-level SDK; the plain mcp SDK now resolves to 2.x and 1.x-era servers crash on it ('Server' object has no attribute 'list_resources'). The pin holds it at 1.x. Each server also declares the pin inline via PEP 723 metadata, so uv run provisions it automatically. See FIX-sqlite-server-pin.md.

Claude Desktop (macOS): put this in ~/Library/Application Support/Claude/claude_desktop_config.json. A ready copy is in config/claude_desktop_config.json. Claude Code: save as .mcp.json in the project root (config/mcp.json). Then fully quit and reopen the host and confirm all three servers connect. If the host can't find uv, use its absolute path (which uv).

Off-the-shelf fallback. A proven variant using the reference mcp-server-sqlite and @modelcontextprotocol/server-filesystem (generic read_query / read_file tools) is committed as config/*.generic.json and prompts/*.generic.md. cp those over the live config and prompt if a purpose-built server ever misbehaves on stage. The beats behave the same; only the tool names differ.

3 · The two prompts

Set the assistant's instructions to one of these (paste as Project instructions in Claude Desktop, or as the first message in Claude Code):

  • assistant-base.md The naive build (Beats A, B, C). No guardrail, so a stale source or a broken tool fools it.
  • assistant-guardrailed.md The same assistant with a guardrail: quote your source and fail closed on missing, errored, or stale data (Beat D).

4 · Run the four beats

Start a new chat for each beat and type the same request every time:

Book me a cheap flight somewhere sunny this weekend and use my miles. I'm Jordan Rivera.
BeatToggle (terminal)PromptOutcome
A · happy path ./scripts/setup.sh base Books San Diego $149, sunny, 12k miles (correct)
B · stale source ./scripts/use-stale.sh base Books Phoenix $129 on 5-day-old weather (it's really a storm)
C · tool error ./scripts/use-current.sh
./scripts/break-miles.sh		 base Loyalty server errors → books anyway (fail open)
D · guardrail swap to the guardrailed prompt guardrailed Catches both: refuses on the error, flags the stale weather

Reset any time with ./scripts/setup.sh.
